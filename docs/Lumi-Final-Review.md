# Lumi 코드 리뷰 최종 재점검

점검일: 2026-11-03. 기준은 이 채팅에 사용자가 붙여 준 루미의 원래 리뷰 항목과 현재 리뷰 브랜치의 실제 코드입니다. 새로운 이벤트·설정 기능의 추가를 리뷰 반영 완료와 혼동하지 않았습니다.

## 결론

요청된 코드 개선의 핵심은 반영되어 있습니다. 다만 직전 구현에도 경계 조건과 정리 누락이 있어 이번 재점검에서 추가 수정했습니다. 모든 문장을 기계적으로 적용한 것은 아니며, 의미 있는 초기화는 유지했습니다. 실기기 검증이나 별도 학습 과제까지 완료했다고 볼 수는 없습니다.

## 항목별 대조

## 이번에 발견하고 수정한 문제

### 1. 원본 DB가 없을 때 정상 백업을 빈 데이터로 덮어쓸 가능성

직전 코드는 원본 파일이 사라져도 ModelContainer를 만들었습니다. SwiftData가 새 빈 DB를 생성하면 시작 백업이 기존 백업을 대체할 수 있었습니다. `PersistentStoreLoader.open()`은 백업이 있으면서 원본이 없는 경우 컨테이너 생성을 중단하고 복원을 안내합니다. 회귀 검사에서 컨테이너 생성 시도가 0회인 것을 확인했습니다.

### 2. 완료 후 도착하는 알림 실패와 겹치는 예약

OS의 예약 추가나 권한 결과를 기다리는 동안 해당 날짜가 완료될 수 있습니다. 성공·실패 양쪽에서 현재 날짜·완료 상태·알림 사용 여부를 다시 확인하도록 했습니다. 이미 의미가 없어진 요청의 실패를 오류로 남기지 않습니다.

동시에 이전 제목과 수정된 제목으로 요청하면 느린 이전 요청이 마지막에 적용될 수도 있었습니다. `NotificationManager`는 OS 쓰기를 순서대로 처리하고 대기 중 최신 챌린지를 다시 읽습니다. 실제 플랫폼 경계 대신 주입한 지연 호출로 중첩 요청과 완료를 재현했습니다.

### 3. 완료 연출의 지연 작업과 동작 줄이기

`CompletionEventView`의 독립 Task는 화면 소멸과 함께 취소되지 않았습니다. View의 `.task(id:)`로 옮기고 화면 소멸 시 반복 상태를 정리합니다. 비활성/Reduce Motion 상태에서는 정적인 최종 모습으로 전환합니다. Growth와 부모의 지연 종료도 취소 상태를 확인합니다. 이 UI 생명주기 변경은 빌드와 코드 검토로 확인했으며 모든 기기 전환 조합을 UI 자동화로 검증한 것은 아닙니다.

### 4. 같은 형태의 init 정리 누락과 Preview 강제 종료

GalaxyPoint만 정리되어 있던 대입 전용 init을 GalaxyStar·GalaxyBody에도 적용했습니다. `let revealAt = 0`으로 고정하지 않고 조절 가능한 입력을 유지했습니다. Preview의 `try!`도 실패 안내로 바꿨습니다. 프로덕션 앱/위젯 소스에서 `fatalError`, `try!`, `GalaxyOrbitModifier`가 남아 있지 않음을 검색으로 확인했습니다.

## 검증의 의미와 한계

- 독립 회귀 실행기는 임시 파일만 사용합니다. 실제 SQLite/WAL 백업·복원, SwiftData 관계·회고 재열기, 손상/없는 백업 거부, 원본 누락 시 빈 DB 생성 차단, 위젯 손상 fallback, 알림 실패·완료 경합·예약 순서를 검사합니다.
- 새 알림 경합 검사를 이전 NotificationManager에 적용하면 실패하고 수정본에서는 통과합니다. 이전 코드 비교용으로는 테스트 시각 주입만 추가했고, 실제 예약/오류 처리 동작은 바꾸지 않았습니다.
- 최종 Debug·Release 빌드는 앱과 임베디드 위젯을 함께 검사합니다. `git diff --check`도 수행합니다.
- 앞선 별도 시뮬레이터에서 손상된 DB 복원과 제목의 DB/백업/위젯 파일 일치를 확인했습니다. 이번 재점검은 그 증거에 추가 회귀 검사와 코드 검토를 더한 것입니다.
- 정상 백업이 없던 손상, 백업 이후 기록, 모든 스키마 업그레이드/공간 고갈/강제 종료 조합은 보장하지 않습니다. 실제 알림 전달·홈 화면 위젯의 갱신 시각·실기기 FPS 및 배터리는 별도 검증이 필요합니다.

백업 복구와 위젯 저장 방식의 자세한 설명은 [구현 보고서](Recovery-and-View-Optimization.md)에 있습니다. 학습 내용은 [Day 7 노트](Day-7-Study-Review.md)에 있습니다. 같은 리뷰 브랜치에서 작업하며 PR·머지는 하지 않습니다.

최종 실행 결과: Debug·Release 앱/위젯 빌드 모두 경고 없이 성공, 전체 회귀 실행기 성공, `git diff --check` 통과. 이전 알림 코드 비교 실행은 완료 중 예약 실패 검사에서 의도대로 실패했습니다. 수정된 프로덕션 코드에서는 같은 검사와 최신 제목 예약 순서 검사 모두 통과했습니다.
