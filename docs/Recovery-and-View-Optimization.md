# DB 복구·알림·위젯 오류 처리와 뷰 최적화

작성일: 2026-11-03. 기존 리뷰 브랜치의 후속 작업이며 PR·머지는 하지 않습니다.

## 1. DB: 재시도에서 백업 복원까지

기존에는 저장소를 열지 못했을 때 앱 종료 대신 안내와 재시도만 제공했습니다. 이제 정상적으로 열었을 때, 명시적 저장이 성공했을 때, 앱이 백그라운드로 갈 때 복구 백업을 갱신합니다. 실패한 저장은 백업 갱신 신호를 보내지 않습니다. 백업 작업은 직렬화하며 작업 중 새 저장이 발생하면 한 번 더 갱신합니다.

`PersonalUniverse/Model/StoreBackup.swift`는 SQLite 온라인 백업 API로 커밋된 WAL 내용까지 포함한 독립 파일을 만들고 `quick_check`를 통과한 경우에만 기존 백업을 교체합니다. 파일을 단순 복사해 최신 WAL 내용을 놓치는 방식을 피했습니다. 백업 생성과 복원 파일 작업은 메인 스레드 밖에서 수행합니다. 복원 시 기본 DB는 원자적으로 교체하며 임시 백업 sidecar는 정리합니다. 실제 저장소 경로는 `ModelConfiguration.url`에서 가져와 App Group 설정도 따릅니다. 백업 실패는 화면 안내와 재시도로 연결됩니다.

저장소 열기에 실패하면 `PersonalUniverseApp.swift`의 `DatabaseRootView`에서 백업 날짜와 복원 버튼을 제공합니다. 확인 메시지에는 백업 이후 변경분이 없을 수 있다는 점을 안내합니다. 복원 전에 현재 `.store`, `-wal`, `-shm` 파일을 `UniverseRecovery/BeforeRestore-<UUID>/`에 별도로 보존합니다. 손상되거나 없는 백업은 거부하며, 저장소가 이미 열렸을 때는 복원하지 않습니다. 백업이 없으면 DB 초기화 없이 그 사실을 안내합니다.

이는 **검사된 백업으로 되돌리는 복구**입니다. 백업이 없던 기존 손상을 복원하거나 모든 손상 데이터를 자동으로 복구하는 기능은 아닙니다. 버전 비호환은 SQLite 무결성 검사만으로 해결되지 않으며, 백업이 앱에서 열리지 않아도 원본과 백업을 보존합니다. 기기 저장 공간 고갈·OS 강제 종료·실제 마이그레이션의 모든 조합을 검증한 것은 아닙니다.

저장 성공 통지는 `Model/ModelContext+Recovery.swift`에 두고 생성·완료·회고·위치 저장·제목/스타일 설정 저장에서 사용합니다. 회고와 설정의 임시 입력은 기존처럼 별도 draft로 유지합니다. SwiftData 스키마는 변경하지 않았습니다.

## 2. 알림: 로그에서 사용자 안내·재시도로

`Manager/NotificationManager.swift`가 권한 거절, 권한 요청 실패, 날짜 오류, 예약 실패를 관찰 가능한 상태로 제공합니다. 권한 거절에는 Settings 이동 버튼, 일시적 실패에는 재시도를 제공합니다. 알림 실패 때문에 이미 저장된 챌린지가 저장되지 않았다고 표시하지 않습니다.

같은 식별자의 새 예약이 실패하기 전에 기존 예약을 먼저 지우던 동작을 제거했습니다. 동일 식별자로 대체 예약을 요청하며, 요청 전에 앱이 기존 예약을 삭제하지 않습니다. OS 내부 실패 처리까지 보장한다는 의미는 아닙니다. 완료·비활성·알림 끄기는 예약을 취소합니다. 권한 요청이나 예약을 기다리는 사이 챌린지가 바뀌거나 완료되었을 때도 상태를 다시 확인합니다. 이미 지난 오늘 알림 시간은 오류가 아니라 예약하지 않는 정상 분기입니다.

플랫폼 호출은 `NotificationClient`로 분리하여 실제 기기 권한을 변경하지 않고 실패를 테스트할 수 있게 했습니다. 기존 `shared` 접근은 유지하되 독립 인스턴스에 테스트 의존성을 주입할 수 있습니다. ViewModel을 추가한 것이 테스트 가능성의 원인은 아닙니다.

## 3. 위젯: 원자적 스냅샷과 이전 정상 데이터

`PersonalUniverseWidget/WidgetSnapshotStore.swift`를 앱과 위젯이 함께 사용합니다. App Group에 작은 JSON 파일을 원자적으로 기록하고 직전의 읽을 수 있는 스냅샷도 남깁니다. 기존 UserDefaults 형식은 업그레이드 시 읽을 수 있도록 유지합니다.

- 공유 저장소 접근·인코딩·쓰기 실패: 앱에서 안내하고 최신 데이터로 재시도합니다. 앱의 SwiftData 저장은 유지합니다.
- 현재 위젯 파일 손상: 이전 정상 스냅샷을 표시하고 `Older progress · Open app`을 표시합니다.
- 읽을 수 있는 스냅샷이 전혀 없음: 앱에서 새로고침하라는 안내를 표시합니다.
- 같은 데이터 반복 전달: JSON 키 순서를 고정하고 동일한 파일이면 쓰기와 타임라인 갱신 요청을 생략합니다. 오류 복구 직후에는 갱신을 요청합니다.

`reloadTimelines`는 OS에 하는 요청이므로 실제 갱신 시각이나 알림 전달을 보장하지 않습니다. 실제 홈 화면 위젯과 잠금 화면 알림 전달은 실기기 확인이 필요합니다.

## 4. 뷰: 실제 반복 작업 줄이기

| 위치 | 이전 | 변경 후 |
|---|---|---|
| `Background/SpaceBackground.swift` | 70개 별을 별도 View로 매 프레임 평가 | Canvas 한 곳에서 같은 별 위치·크기·밝기 계산으로 그림 |
| `Galaxy/GalaxyView.swift` | computed 배열을 접근할 때마다 동일한 seeded 별·먼지·천체 생성 | 스타일별 불변 배열을 한 번 생성해 재사용. 진행도와 reveal 계산은 계속 동적으로 적용 |
| `Views/CurrentChallengeView.swift`, `CompletionEventView.swift` | 부모 배경 위에 별·이벤트 배경을 다시 그림 | 화면을 소유하는 부모에서 한 번만 그림. 독립 Preview에는 배경을 명시 |
| 배경·은하 | 화면이 사라진 뒤에도 일부 반복 애니메이션 유지 가능 | 표시 여부, scenePhase, Reduce Motion을 기준으로 중지. 재진입/스타일 변경 때 애니메이션 상태 재생성 |
| `Views/ContentView.swift` | 비활성 중에도 분 단위 갱신 루프 유지 | 활성 상태에서만 실행, 비활성 시 취소. 복귀 시 즉시 갱신 |
| `Model/UniverseChallenge.swift` | 같은 status를 반복 대입 | 실제 값이 바뀔 때만 대입하여 불필요한 변경/저장 줄임 |

장식 이벤트의 배치는 여전히 **별 배경 → 이벤트 → 콘텐츠**이며 터치를 가로채지 않습니다. 디자인·난수 간격·진행 규칙은 유지했습니다. 이 변경은 반복 생성·중복 렌더링을 줄인 근거가 있는 최적화입니다. 실기기 FPS나 배터리 개선율을 측정했다고 주장하지 않습니다.

Canvas 선택은 Apple의 [Canvas 문서](https://developer.apple.com/documentation/swiftui/canvas)를, 일관된 DB 스냅샷 방식은 [SQLite 온라인 백업 API](https://www.sqlite.org/backup.html)를 확인했습니다.

## 5. 검증

`bash Tests/Day7Regression/run.sh`는 실제 프로덕션 모델과 작업 코드를 컴파일하는 독립 실행 테스트입니다. 사용자 DB를 건드리지 않고 임시 저장소만 사용합니다.

- 기존 메타데이터 저장/실패/초기 로딩 재시도·revealAt·난수 이벤트 검사.
- 열린 WAL DB의 최신 커밋 백업, 연속 백업 교체, 원본 DB·WAL·SHM 보존과 복원.
- 백업 없음/손상된 백업/손상된 원본에서 정상 백업을 덮어쓰지 않는 동작.
- 실제 SwiftData 백업을 다시 열어 제목·스타일·7일 관계·완료 상태·회고 내용 보존 확인.
- 위젯 스냅샷 중복 생략, 손상 시 이전 버전, 복구, 파일 쓰기 실패.
- 알림 권한 거절/요청 실패/복구, 예약 실패와 재시도, 기존 예약 선삭제 방지, 알림 끄기 시 취소.

별도 `Personal Universe Recovery QA` 시뮬레이터에 `Recovery QA` 테스트 챌린지를 만들고, 원본 사본과 정상 백업을 남긴 뒤 테스트 DB만 손상시켰습니다. 오류 화면·백업 날짜·복원 확인 메시지·복원 후 동일 제목 재표시를 확인했습니다. 서명 없는 시뮬레이터 빌드에서는 App Group 접근 실패 안내도 실제 화면에서 확인했습니다.

전체 제품의 릴리스 승인, 모든 저장 공간 오류/스키마 업그레이드 조합, 실기기 알림 전달 및 성능 측정까지 완료했다는 의미는 아닙니다. Lumi의 초기화·상수·아키텍처 학습 및 TCA/Confluence 실습은 이 기능 구현과 구분합니다.

로컬 서명을 적용한 시뮬레이터 빌드에서는 App Group 오류 안내가 사라졌고, 설정에서 `Recovery QA updated`로 수정한 제목이 화면·실제 SwiftData 저장소·복구 백업·공유 위젯 JSON 모두에 일치하는 것을 확인했습니다. 서명된 앱의 SwiftData 저장소는 App Group 아래에 있으므로 검사는 해당 경로에서 수행했습니다.

최종 Debug·Release 앱/위젯 빌드가 경고 없이 통과했고, 확장된 회귀 검사와 `git diff --check`도 통과했습니다. 원자적·비동기 복원을 적용한 최종 서명 빌드에서도 App Group의 테스트 DB를 손상시킨 뒤 `Recovery QA updated` 제목으로 복원되는 것을 다시 확인했습니다. 연속 백업 검사에는 첫 백업 이후의 WAL 변경분 반영과 임시 sidecar 정리도 포함됩니다.
